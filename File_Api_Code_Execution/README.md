# Streaming Service Churn Analysis

This project analyzes a sample streaming-service customer dataset to explore churn patterns and identify potential drivers of customer churn. The analysis is orchestrated from a Jupyter notebook and uses a Groq-powered code agent to run Python analysis in a separate local process within a project workspace.

## Project contents

| Path | Description |
| --- | --- |
| `code_execution.ipynb` | Main notebook: configures the Groq client and local file tools, stages the data, and runs the analysis workflow. |
| `streaming.csv` | Input dataset containing 500 customer records and 10 fields. |
| `code_workspace/_run.py` | Python analysis script generated in the code workspace. |
| `code_workspace/streaming.csv` | Staged copy of the input dataset used by the analysis script. |
| `code_workspace/churn_summary.png` | Summary figure with churn rates, feature importance, and a correlation matrix. |
| `code_workspace/churn_analysis.png` | Additional analysis visualization generated by the notebook workflow. |

The dataset includes subscription tier, viewing and engagement measures, customer-service interactions, monthly cost, and a binary `Churned` field.

## Requirements

- Python 3
- Jupyter Notebook
- A Groq API key

The notebook uses these Python packages:

```text
groq
python-dotenv
requests
pandas
numpy
matplotlib
seaborn
scikit-learn
```

Install the packages in your Python environment:

```bash
python -m pip install jupyter groq python-dotenv requests pandas numpy matplotlib seaborn scikit-learn
```

## Configure the API key

Set `GROQ_API_KEY` in your environment before starting Jupyter. Alternatively, create a `.env` file in the project folder:

```dotenv
GROQ_API_KEY=your_groq_api_key
```

Do not commit your `.env` file or API key to GitHub.

## Run the project

1. Open a terminal in the project folder and start Jupyter:

   ```bash
   jupyter notebook
   ```

2. Open `code_execution.ipynb`.
3. Run the notebook cells from top to bottom. The notebook uploads and stages `streaming.csv`, asks the Groq-powered agent to inspect and analyze the data, runs generated Python code in `code_workspace`, and displays the resulting summary and plots.

The code runner starts a fresh Python process for each execution. Each generated code run must therefore import its own dependencies and recreate any variables it needs.

## Analysis and outputs

The workflow explores overall churn, churn by subscription tier and genre, relationships between numeric customer measures and churn, and feature importance from a Random Forest model. The generated charts are saved in `code_workspace`.

The included `_run.py` provides a standalone example of the analysis. Run it from `code_workspace` so it finds the staged dataset and saves the chart there:

```bash
cd code_workspace
python _run.py
```
